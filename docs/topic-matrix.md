# Матрица тем

Агент относит запрос клиента к теме и показывает модели только инструменты этой темы.
Документ собирается из `agent/topics.toml`, кода инструментов и SDK `apisdkopti24`
скриптом `python scripts/generate_topic_matrix.py`: не правьте его вручную.

Как это работает:

1. Быстрый путь. Классификатор (`agent/classifier.py`) сравнивает вопрос с ключевыми словами тем.
   Если главная тема набрала не меньше 2 и строго больше следующей, она считается
   уверенной: модель получает подсказку (тема, цель, инструменты, чего не хватает), а у
   OpenAI-совместимых провайдеров сразу видит инструменты темы.
2. Смысловой путь. Если уверенности нет (перефразировки, разговорные слова, ничья двух тем),
   подсказки нет: модель сама выбирает тему по каталогу разделов и тем в инструкции и открывает
   её или весь раздел вызовом `open_toolbox`, который скажет, что спросить у пользователя.
3. Без обязательного параметра (например, карты для разбора отказа) модель сначала спрашивает
   пользователя и не тратит тарифицируемые запросы. У Claude видны все инструменты, каталог тем — в инструкции.

Как пополнять: добавьте реальный вопрос клиента в `examples` подходящей темы (или заведите
тему), допишите `keywords`, запустите `pytest` и этот скрипт. Реальные вопросы можно собирать
журналом `AGENT_TOPIC_LOG=путь.jsonl`: он включается явно и хранится только у вас.

Тем: 26, из них 22 агент выполняет, 4 — вне его задач.

## Темы подробно

### Баланс договора (`balance`)

Узнать, сколько денег осталось на договоре и хватит ли их

Примеры запросов: «Сколько денег осталось на договоре?»; «Какой у нас баланс?»; «Хватит ли денег до конца месяца?».

Инструменты и методы SDK:

- `get_contract_summary` → `get_contract_data` (тарифицируемый), `get_dictionary` (бесплатный)

Данные из ответа SDK:

- `get_contract_data` → `data.balanceData.available_amount` — Доступный остаток
- `get_contract_data` → `data.balanceData.own_balance` — Собственные средства
- `get_contract_data` → `data.balanceData.consumption_for_month` — Расход в текущем месяце (в валюте контракта)
- `get_contract_data` → `data.balanceData.last_payment_sum` — Сумма последнего платежа
- `get_contract_data` → `data.balanceData.last_payment_date` — Дата последнего платежа

Справочники для расшифровки: `DiscountScheme` (схемы расчёта скидки), `PaymentTerm` (условия оплаты договора), `PaymentScheme` (схемы оплаты договора).

Параметры: —.

Важно: «Доступно» — available_amount; лимитные поля договора не путать с остатком денег. Прогноз — только по просьбе.

### Расходы (`spending`)

Узнать, сколько потратили на топливо за период

Примеры запросов: «Сколько мы потратили на топливо в сентябре 2026?»; «Сколько потратили в прошлом месяце?»; «Покажи расходы».

Инструменты и методы SDK:

- `spending_report` → `get_transactions_v2` (тарифицируемый), `get_card_transactions_v2` (тарифицируемый)

Данные из ответа SDK:

- `get_transactions_v2` → `data.result.sum` — Сумма с учетом скидки
- `get_transactions_v2` → `data.result.qty` — Количество
- `get_transactions_v2` → `data.result.product_name` — Наименование продукта
- `get_transactions_v2` → `data.result.card_id` — ID карты

Параметры: период — по умолчанию текущий месяц.

Важно: Операции видны через 1–2 часа после заправки. Период больше месяца делится на месяцы.

- `fuel_price_analytics` → `get_transactions_v2` (тарифицируемый), `get_card_transactions_v2` (тарифицируемый), `get_azs_list_v1` (бесплатный), `get_dictionary` (бесплатный)
- `get_contract_summary` → `get_contract_data` (тарифицируемый), `get_dictionary` (бесплатный)

Данные из ответа SDK:

- `get_transactions_v2` → `data.result.price` — Цена за единицу
- `get_transactions_v2` → `data.result.price_no_discount` — Цена без скидки
- `get_transactions_v2` → `data.result.sum` — Сумма с учетом скидки
- `get_transactions_v2` → `data.result.sum_no_discount` — Сумма без скидки
- `get_transactions_v2` → `data.result.qty` — Количество
- `get_contract_data` → `data.balanceData.consumption_for_prev_month_volume` — Объем потребления в предыдущем месяце (в литрах)

Параметры: период — по умолчанию текущий месяц; вид топлива — если есть.

Важно: Ставка сбора — по объёму прошлого месяца (consumption_for_prev_month_volume) и таблице 3 Приложения № 1; это типовая редакция.

Примеры запросов: «Покажи активные карты»; «Покажи группы карт»; «Какие карты есть на договоре?».

Инструменты и методы SDK:

- `list_cards` → `get_cards_v2` (бесплатный)
- `list_card_groups` → `get_card_groups` (бесплатный)

Данные из ответа SDK:

- `get_cards_v2` → `data.result.number` — Номер топливной карты
- `get_cards_v2` → `data.result.status_name` — Отображаемое имя статуса (например 'Активна')
- `get_cards_v2` → `data.result.group_name` — Название группы карт
- `get_cards_v2` → `data.result.comment` — Комментарий, установленный пользователем
- `get_card_groups` → `data.result.name` — Название группы карт
- `get_card_groups` → `data.result.cards_count` — Количество карт в группе

Параметры: —.

Важно: При нескольких совпадениях — уточнить; номер и ID показывать как в ответе.

### Профиль карты (`card_profile`)

Узнать, кто водитель карты, когда и где она использовалась

Примеры запросов: «Кто водитель на карте 7826010000000001?»; «Когда последний раз заправлялись по карте Газели?»; «Какая карта закреплена за Газелью Иванова?».

Инструменты и методы SDK:

- `list_cards` → `get_cards_v2` (бесплатный)
- `get_card_profile` → `get_card_detail` (тарифицируемый), `get_cards_v2` (бесплатный), `get_card_drivers` (тарифицируемый), `get_limits` (бесплатный), `get_dictionary` (бесплатный)

Данные из ответа SDK:

- `get_card_detail` → `data.result.date_last_usage` — Дата последнего использования (YYYY-MM-DD); пустую строку SDK заменяет на None
- `get_card_detail` → `data.result.servicecenter_last_usage_name` — Название АЗС последнего использования
- `get_card_detail` → `data.result.available` — Доступный лимит или баланс
- `get_card_drivers` → `data.result.last_name` — Фамилия водителя

Параметры: карта — спросить: «О какой карте речь? Номер, ID или комментарий (машина, водитель).».

Важно: Персональные данные водителя показывать только по прямому вопросу.

### Лимиты и правила (`limits`)

Посмотреть лимиты, региональные правила и товарные ограничители

Примеры запросов: «Какие лимиты на карте Газели Иванова?»; «Покажи лимиты по договору»; «Покажи регионы и ограничители по карте c1».

Инструменты и методы SDK:

- `get_limits` → `get_limits` (бесплатный), `get_dictionary` (бесплатный)
- `get_access_rules` → `get_limits` (бесплатный), `get_region_limits` (тарифицируемый), `get_restrictions` (тарифицируемый), `get_dictionary` (бесплатный)
- `list_cards` → `get_cards_v2` (бесплатный)

Данные из ответа SDK:

- `get_limits` → `data.result.amount.value` — Установленное значение лимита
- `get_limits` → `data.result.amount.used` — Использованное значение лимита
- `get_limits` → `data.result.sum.value` — Сумма лимита
- `get_limits` → `data.result.sum.used` — Использованный объём лимита
- `get_limits` → `data.result.time.type` — Тип периода (например, 7 — неделя)
- `get_region_limits` → `data.result.region` — Код регион обслуживания
- `get_region_limits` → `data.result.limit_type` — Тип лимита
- `get_restrictions` → `data.result.productTypeName` — Название типа продукта
- `get_restrictions` → `data.result.restriction_type` — Тип ограничения (1 – Разрешающий ограничитель, 2 – Запрещающий ограничитель)

Справочники для расшифровки: `ProductType` (типы продуктов).

Параметры: —.

Важно: Карту, группу или весь договор. Региональные лимиты и ограничители — 2 тарифицируемых запроса.

### Отказ на АЗС (`refusal`)

Понять, почему карту не приняли на АЗС

Примеры запросов: «Почему карта c1 не работает?»; «Водителю на АЗС 137 отказали в заправке по карте c1, ДТ 50 литров. В чеке отказа код ответа ER3, текст «Операция прервана». Почему?»; «Водителю не дали заправиться по карте c1, в чеке код ответа 51. Что случилось?».

Инструменты и методы SDK:

- `diagnose_fueling` → `get_cards_v2` (бесплатный), `get_card_detail` (тарифицируемый), `get_limits` (бесплатный), `get_contract_data` (тарифицируемый), `get_region_limits` (тарифицируемый), `get_restrictions` (тарифицируемый), `get_azs_list_v1` (бесплатный), `check_purchase` (бесплатный, только рабочий API), `get_dictionary` (бесплатный)

Данные из ответа SDK:

- `get_card_detail` → `data.result.status` — Статус карты
- `get_card_detail` → `data.result.pin_counter` — Счётчик попыток ввода PIN
- `get_limits` → `data.result.amount.used` — Использованное значение лимита
- `get_contract_data` → `data.balanceData.available_amount` — Доступный остаток
- `get_region_limits` → `data.result.limit_type` — Тип лимита
- `get_restrictions` → `data.result.restriction_type` — Тип ограничения (1 – Разрешающий ограничитель, 2 – Запрещающий ограничитель)

Справочники для расшифровки: `Goods` (виды топлива для цен на АЗС), `ProductType` (типы продуктов).

Параметры: карта — спросить: «По какой карте отказ? Номер, ID или комментарий.»; код ответа из чека — если есть; АЗС — если есть; вид топлива — если есть; литры — если есть.

Важно: Порядок: статус → check_purchase → лимит → баланс → регион и ограничитель → PIN. Код из чека — по таблице Приложения № 4.

### Блокировка карт (`block_card`)

Заблокировать или разблокировать карту

Примеры запросов: «Заблокируй карту 7826010000000001, водитель уволился»; «Заблокируй все карты»; «Разблокируй карту Газели».

Инструменты и методы SDK:

- `list_cards` → `get_cards_v2` (бесплатный)
- `block_cards` → `block_card` (тарифицируемый)

Данные из ответа SDK:

- `get_cards_v2` → `data.result.number` — Номер топливной карты
- `get_cards_v2` → `data.result.status_name` — Отображаемое имя статуса (например 'Активна')

Параметры: карта — спросить: «Какие карты заблокировать? Номера или комментарии, массовая блокировка не выполняется.»; причина — спросить: «Причина блокировки (например, увольнение водителя или утеря карты)?».

Важно: Только по конкретным картам и прямой просьбе; подтверждение человека; в read_only — отказ.

### Изменение правил (`change_rules`)

Изменить лимит, разрешить или запретить регион или вид топлива

Примеры запросов: «Поставь лимит 300 литров в месяц на карту c1»; «Запрети заправку в Москве по карте c1»; «Разреши только ДТ по карте c1».

Инструменты и методы SDK:

- `get_access_rules` → `get_limits` (бесплатный), `get_region_limits` (тарифицируемый), `get_restrictions` (тарифицируемый), `get_dictionary` (бесплатный)
- `set_limit` → `set_limit` (тарифицируемый)
- `set_region_limit` → `set_region_limit` (тарифицируемый)
- `set_restriction` → `set_restriction` (тарифицируемый, только рабочий API)
- `remove_limit` → `remove_limit` (тарифицируемый)
- `remove_region_limit` → `remove_region_limit` (тарифицируемый)
- `remove_restriction` → `remove_restriction` (тарифицируемый)

Данные из ответа SDK:

- `get_limits` → `data.result.id` — ID лимита
- `get_region_limits` → `data.result.id` — ID регионального лимита
- `get_restrictions` → `data.result.id` — ID ограничителя

Параметры: карта — спросить: «Для какой карты или группы изменить правило?»; размер — если есть.

Важно: Сначала показать текущее правило и новое; подтверждение человека; код периода не угадывать.

### Платежи (`payments`)

Посмотреть платежи по договору

Примеры запросов: «Покажи платежи за сентябрь 2026»; «Когда был последний платёж?».

Инструменты и методы SDK:

- `get_finance` → `get_payments` (тарифицируемый), `get_invoices` (бесплатный), `get_documents` (бесплатный, только рабочий API)

Данные из ответа SDK:

- `get_payments` → `data.result.date` — Дата и время платежа в формате ISO 8601 (например, 2015-04-15T15:25:20)
- `get_payments` → `data.result.amount` — Сумма платежа в валюте договора
- `get_payments` → `data.result.payment_name` — Наименование типа платежа, например 'Payment To Client Contract'

Параметры: период — по умолчанию текущий месяц.

Важно: Платежи — тарифицируемый запрос; последний платёж есть и в сводке договора.

### Счета и документы (`documents`)

Найти счета и закрывающие документы

Примеры запросов: «Покажи закрывающие документы за сентябрь 2026»; «Есть ли неоплаченные счета?».

Инструменты и методы SDK:

- `get_finance` → `get_payments` (тарифицируемый), `get_invoices` (бесплатный), `get_documents` (бесплатный, только рабочий API)

Данные из ответа SDK:

- `get_invoices` → `data.result.amount` — Сумма счёта

Параметры: период — по умолчанию текущий месяц.

Важно: Счета и документы бесплатны; документы только на рабочем API.

### Справочники (`dictionaries`)

Узнать, что значит код или какие бывают значения: статусы, схемы скидок, условия оплаты, услуги АЗС

Примеры запросов: «Какие бывают статусы карт?»; «Что значит схема скидки в договоре?»; «Какие услуги бывают на АЗС?»; «Какие офисы продаж есть?».

Инструменты и методы SDK:

- `lookup_dictionary` → `get_dictionary` (бесплатный)

Данные из ответа SDK:

- `get_dictionary` → `data.result.name` — Название элемента (используется в новых справочниках)
- `get_dictionary` → `data.result.code` — Код элемента (например, код валюты)

Справочники для расшифровки: `CardStatus` (статусы карт), `ContractStatus` (статусы договоров), `DiscountScheme` (схемы расчёта скидки), `PaymentTerm` (условия оплаты договора), `PaymentScheme` (схемы оплаты договора), `Services` (услуги на АЗС), `Office` (офисы продаж), `POIPartner` (партнёры (сети АЗС)), `POIType` (типы торговых точек), `Goods` (виды топлива для цен на АЗС), `ProductType` (типы продуктов), `Region` (регионы).

Параметры: —.

Важно: Справочники бесплатны; агент сам расшифровывает ими коды в сводке договора, лимитах и регионах.
